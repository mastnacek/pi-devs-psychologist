# Audit 2026-09-29 — three surfaces against the pi-plugin-dev skill

Run because the previous fix (two settings-menu rows that contradicted each other and leaked a
raw i18n key) was found by *reading* a reference, not by running anything. That is the failure
mode this audit exists to remove: three surfaces checked against the skill by executing them.

**Result: 1 FAIL and 2 real defects found and fixed; 10 warnings investigated and shown to be
cross-file false positives; 4,478 rendered lines swept with zero width violations afterwards.**

---

## Method

The reference was read first, then every surface was exercised through its real code path rather
than inspected:

- **Width safety** (`references/tui-and-components.md` §1): every card view rendered at
  9 widths × 2 locales with adversarial content (a 240-char string, CJK, emoji, an every-field-set
  appraisal), plus the report on all four of its paths. `visibleWidth` measured, never `.length`.
  Now permanent: `test/width-safety.test.js`.
- **Multilingual** (`references/multilingual-ui.md`): the `multilingual-ui` invariant shipped by
  pi-plugin-dev, run over all 185 source and doc files via its own `auditCodeContent`, plus a
  locale-parity and placeholder check of the table.
- **The table itself**: every key present and non-empty in `en` and `cs` (the existing lint), plus
  two new checks — no value may equal its own key, and no value may be a shouted placeholder.

## Fixed

### 1. FAIL — `multilingual-ui`: the `--psych-runtime` flag description was hardcoded

`index.ts` registered the flag with a literal English string. The engine prints flag descriptions
into `pi --help`, so this is text the **operator** reads, which is the same class of sink the
reference names for `registerCommand`. Verified by running `pi --help`:

```
--psych-runtime <value>     Override the psychologist runtime for this run (api|agent)
```

Fixed: new `flagPsychRuntime` key in `en` and `cs`, resolved at registration from
`loadConfig(undefined, globalFile).lang` — the saved machine-wide language. A flag is registered
before the project layer of the cascade is known, so the global preference is the only correct
choice, and it is the one `--help` readers have. Regression test in `test/extension.test.js`
drives the real `registerFlag` in both locales.

### 2. Width — the report's two early returns bypassed the clip

The main 39-line path clips through `clipRender`. The two early returns did not:

| path | width 40 | width 20 |
|---|---|---|
| no model configured | **76 cells** | overflow |
| disabled | overflow | **2 lines over** |

"⚠ No psychologist model configured. Set one with: `/psych model …`" is the longest prose in the
report, and it is one of the **first two things** an operator sees, before they have configured a
model. A notification wraps rather than crashes, so this was presentation, not a crash — but the
rule exists because a wrapped row is indistinguishable from a broken one. Both returns now clip.

### 3. Portability — a machine path in a runnable script

`scripts/live-agent-check.mts` hardcoded `D:/02_knihovny_path/node-v22.17.1-win-x64/…`. It would
fail on the next node upgrade. The auditor **cannot see it** — it scans `.ts/.js/.json/.md` and the
file is `.mts` — so nothing would ever have said so. Now resolved at runtime from
`PI_PACKAGE_DIR`, the local `node_modules`, or the versioned store beside `process.execPath`.
`docs/agent-runtime-spike.md` carried the same literal; it is a measurement record, so the path is
now a labelled `<engine root>` with instructions for re-deriving it.

## Investigated and dismissed: 10 warnings, all cross-file false positives

Each was checked by driving the real composition root, not by reading.

| Warning | Files | Verdict |
|---|---|---|
| `lifecycle-cleanup` — "unsubscribers stored but never drained" | `appraiser`, `handoff`, `observer` | **False positive.** The slices call `state.track(pi.on(…))`; the drain lives in the composition root (`index.ts:389`), which is where VSA puts it. Driven: **9 subscriptions opened, all 9 drained on shutdown.** The auditor looks for a drain in the same file. |
| `state-persistence` — "appendEntry with no sessionManager read" | `appraiser/index.ts`, `appraiser/ledger.ts` | **False positive.** The read is at `index.ts:246-248` (`getEntries` → `restoreAppraisal` / `restoreOutcomes`). Driven with a pre-seeded session: the report after the "reload" renders the restored `Competence: at risk`. The existing `persistence.test.js` covers the ledger rebuild. This is the same structural split that hid the handoff bug, so it was worth driving rather than assuming. |
| `trailing-space` — "no non-terminal completion row found" | `commands/index.ts` + 4 test files | **False positive.** The rows live in `commands/completions.ts`, which passes. `commands/index.ts` re-exports `completePsych` and holds no literal rows. Test files are noise. |

The real completion rules were already verified in the previous audit: trailing-space contract,
full prefix replacement, current-value annotation in label **and** description **and** parent row,
no ANSI, no marker in `value`, and lazy parameter completion with no space typed.

## What the audit says about the process

The one FAIL and both real defects were on surfaces I had touched at some point and never re-checked
as a whole: a flag registered in the first release, a report early-return from T27, a script written
for one live test. The pattern is consistent with the three "false proof" bugs found earlier — every
one of them was a check that passed because it exercised the code the way the author imagined, not
the way the engine calls it. Running the surface is what finds these; reading it does not.
